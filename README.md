## ExploreWithMe

---
#### Описание:
На втором этапе основной монолитный сервис main-service был постепенно преобразован в набор независимых микросервисов, 
взаимодействующих через API-шлюз и инфраструктурные компоненты с использованием Spring Cloud и Docker
<br>

#### Схема взаимодействия

Внешний API, доступен клиентам через Gateway, полностью совместим со спецификацией, описанной на этапе группового проекта.
Спецификация OpenAPI: ewm-main-service-spec.json (корневая директория проекта)

> Клиент -> API Gateway (8080) -> Микросервисы

- `Eureka Discovery Server` - регистрация и обнаружение
- `Config Server` - централизованное управление конфигурацией
- `PostgreSQL (5432)` - общий сервер БД

Все внешние запросы приходят только через API Gateway на порт 8080. Он маршрутизирует их к нужному микросервису
<br>

#### Микросервисы

- `event-service` - управление событиями (создание, редактирование, удаление, поиск событий)
- `request-service` - управление заявками на участие
- `user-service` - администрирование пользователей
- `stats-service` - статистика
<br>

#### Инфраструктурные компоненты

- `gateway-server` - единая точка входа для всех клиентских запросов. Настроен на перенаправление запросов к 
соответствующим сервисам
- `discovery-server` - сервер Eureka, обеспечивающий динамическое обнаружение и регистрацию микросервисов
- `config-server` - централизованный сервер конфигурации, откуда все микросервисы загружают свои настройки
<br>

#### Межсервисное взаимодействие

Все вызовы между микросервисами осуществляются через OpenFeign клиенты через REST API. Клиенты находятся внутри 
модуля core -> interaction-api
- `EventClient` - для вызова методов event-service
- `ParticipationRequestClient` - для вызова методов request-service
- `UserClient` - для вызова методов user-service
<br>

#### Конфигурация
Все настройки сервисов хранятся централизованно в репозитории конфигураций, который обслуживается config-server 

> infra/config-server/src/main/resources/config/

Профили запуска:
- `default` - для локальной разработки без Docker
- `docker` - для запуска в контейнерах через docker-compose.yml

```shell
docker compose --profile doker up
```

После успешного запуска система доступна по адресу: http://localhost:8080
<br>

#### Тестирование
Для проверки работоспособности и совместимости используется Postman

Все тестовые коллекции находятся в папке ./postman
Все запросы должны отправляться на http://localhost:8080 (через Gateway)
